# @scaffald/ui usage inventory — generated 2026-06-11

> Mechanical SC-27 prep. Maps every public export to its direct importers across `apps/scaffald` (mobile), `apps/web` (web), and other packages. The refactor decisions live in [SC-27](https://linear.app/scaffald/issue/SC-27) proper.

## Architectural finding

`apps/web` does **not** import `@scaffald/ui` directly — its UI surface is consumed entirely through wrapper packages (`@unicornlove/compliance`, `@unicornlove/tasks`, `@unicornlove/insurance`, `@scf/core`). `apps/scaffald` (mobile) imports the kit directly. This means "shared between mobile and web" isn't a meaningful direct-usage category here — the right axis is direct (mobile) vs indirect-via-wrappers (web).

- **1122** public exports surfaced from `packages/ui/src/index.ts` (recursively following star re-exports through tokens / components / hooks subtrees)
- **956** dead — zero direct imports across all consumers (85%) — primary "comment out / hide" candidates per SC-27
- **32** imported by `apps/scaffald` directly (3%) — mobile-app surface
- **0** imported by `apps/web` directly (0%) — confirms web routes through wrappers
- **134** used only by other packages (12%) — the wrapper-layer surface
- **30** used by both mobile and packages — most-load-bearing exports
- Scanned **1861** consumer files

### Caveats

1. **"Dead" means no direct `from "@scaffald/ui"` importer**, not transitively unused. Some dead exports may be re-exported by a wrapper package and consumed downstream — those re-exports would need a separate trace. Use the dead list as an upper-bound triage queue, not a delete list.
2. Tests and stories under `packages/ui/__tests__/`, `packages/ui/stories/`, `packages/ui/playground/` are excluded from the consumer scan; an export used only by its own tests still counts as dead here.
3. Only destructured-named imports are counted (`import { X } from ...`). Namespace imports (`import * as ui from ...`) are not — there are none currently but adding one would silently undercount.
