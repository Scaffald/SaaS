# Files in this directory that CI runs as a gate — a failure here fails the build.
#
# `tests/routers/` holds HTTP tests against the running `api` edge function.
# This list is a ratchet: every path below passes on a CLEAN stack, which is
# what CI gives it. It may only grow — if a listed file starts failing, fix the
# file or the code it covers rather than deleting the line.
#
# CI starts the stack with plain `supabase start`, so it sees only the env the
# workflow sets, not .env. Delete tests/fixtures/tokens.json before measuring
# a new file.
#
#   cd packages/supabase
#   deno test --allow-all --no-check --config tests/deno.json tests/routers/<file>
#
# Blank lines and lines starting with # are ignored.
#
# The four suites that used to sit here as "assertion drift" — work-logs,
# profileCompletion, payments and education — were deleted rather than
# repaired. They drove the legacy `trpc` edge function, whose routers the app
# no longer calls: those four features reach the `api` function through
# work-logs-sdk-hooks, profile-completion-sdk-hooks, payments-sdk-hooks and
# profile-education-sdk-hooks. Their REST successors need HTTP coverage of
# their own, tracked separately; work-logs-rest.test.ts is the pattern.

# payments-settlement.test.ts is the one file here that does not speak HTTP:
# it drives functions/_shared/payments/settlement.ts against the real database,
# because what it tests is the UPDATE guards themselves. It belongs in the gate
# rather than in tests/unit/ because nothing runs tests/unit/ — in CI or in
# prepush — and this logic decides whether a payment is recorded. It is also
# the test that caught core.payment_transactions having a set_updated_at
# trigger and no updated_at column (migration 361).
