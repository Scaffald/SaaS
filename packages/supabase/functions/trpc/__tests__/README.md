# tRPC Endpoint Testing Guide

This directory contains testing documentation and utilities for the tRPC endpoints with **authentication integration**.

## 🚀 Quick Start

```bash
# 1. Start Supabase (if not already running)
pnpm supa start

# 2. Run all tests in correct order
./packages/supabase/functions/trpc/__tests__/run-tests.sh
```

## 📋 Prerequisites

- Local Supabase instance running (`pnpm supa start`)
- Supabase environment variables set
- Test data seeded in database
- Deno installed for running tests

## 🏗️ Architecture

### Test Execution Flow

```
1. auth.test.ts (RUNS FIRST)
   ↓
   - Registers test user via magic link
   - Authenticates admin user (if available)
   - Caches tokens to fixtures/tokens.json
   ↓
2. integration/*.test.ts
   ↓
   - Loads cached tokens
   - Uses pre-authenticated clients
   - Tests protected endpoints
   ↓
3. Standalone tests (e.g., universities.test.ts)
   ↓
   - Also uses cached tokens
   - Tests specific features
```

### Key Files

- **`setup.ts`** - Utilities for auth, Inbucket, and token caching
- **`test-context.ts`** - Test context manager with pre-authenticated clients
- **`auth.test.ts`** - Authentication tests (must run first)
- **`run-tests.sh`** - Test runner script (executes tests in correct order)
- **`fixtures/tokens.json`** - Cached auth tokens (generated by auth tests)

## 🔐 Authentication Testing

### Magic Link Flow

The test suite uses Supabase's **Inbucket** email testing server to test actual magic link authentication:

1. Request magic link via Supabase Auth API
2. Query Inbucket API to retrieve email
3. Extract magic link URL from email body
4. Complete authentication and get access token
5. Cache token for reuse in other tests

### Token Caching

Tokens are cached to avoid repeated authentication:
- **Location**: `packages/supabase/functions/trpc/__tests__/fixtures/tokens.json`
- **Validity**: 1 hour (configurable in `config.toml`)
- **Automatic refresh**: Re-run auth tests if tokens expire

## 📝 Writing New Tests

### Using Test Context (Recommended)

```typescript
import { getTestContext } from "./test-context.ts";
import { callTRPCEndpoint } from "./setup.ts";

Deno.test({
  name: "My Feature - Test with auth",
  async fn() {
    // Get pre-authenticated context
    const ctx = await getTestContext();

    // Test with anonymous access
    const anonResult = await ctx.anon
      .from("public_table")
      .select("*");

    // Test with regular user auth
    const userResult = await callTRPCEndpoint(
      "myRouter.myProcedure",
      { param: "value" },
      ctx.user.token
    );

    // Test with admin auth
    const adminResult = await callTRPCEndpoint(
      "office.adminProcedure",
      { param: "value" },
      ctx.admin.token
    );
  },
  sanitizeResources: false,
  sanitizeOps: false,
});
```

### Test Context Interface

```typescript
interface TestContext {
  anon: SupabaseClient;           // Anonymous client
  user: {
    client: SupabaseClient;        // Authenticated user client
    token: string;                 // Access token
    email: string;                 // User email
    userId: string;                // User ID
  };
  admin: {
    client: SupabaseClient;        // Authenticated admin client
    token: string;                 // Access token
    email: string;                 // Admin email
    userId: string;                // Admin user ID
  };
}
```

#### ✅ getPublishedJobs
**Purpose**: Fetch published internal jobs with polymorphic skills

**Test Cases**:
1. **No parameters** - Should return all published jobs

   
2. **With search** - Should filter by title/description
   ```bash
   curl "http://127.0.0.1:54321/functions/v1/trpc/jobs.getPublishedJobs?batch=1&input=%7B%220%22%3A%7B%22search%22%3A%22construction%22%7D%7D"
   ```

3. **With pagination** - Should respect limit/offset
   ```bash
   curl "http://127.0.0.1:54321/functions/v1/trpc/jobs.getPublishedJobs?batch=1&input=%7B%220%22%3A%7B%22limit%22%3A5%2C%22offset%22%3A0%7D%7D"
   ```

### Office Router

#### ⚠️ Note: Office endpoints require super admin authentication

**Get Auth Token**:
```bash
# Sign in as admin user
curl -X POST 'http://127.0.0.1:54321/auth/v1/token?grant_type=password' \
  -H "apikey: YOUR_ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@example.com","password":"adminpassword"}'
```

**Use Token in Request**:
```bash
curl "http://127.0.0.1:54321/functions/v1/trpc/office.getJob?batch=1&input=%7B%220%22%3A%7B%22id%22%3A%22JOB_UUID%22%7D%7D" \
  -H "Authorization: Bearer YOUR_TOKEN_HERE"
```

## Validating Polymorphic Skills

When testing job endpoints, verify that skills are returned with:
1. `id` - The skill identifier (CSI UUID or O*NET code)
2. `name` - The skill name
3. `taxonomy` - Either "csi" or "onet"

Example validation:
```javascript
// Check if skills are properly transformed
const job = response.result.data.jobs[0];
if (job.skills && job.skills.length > 0) {
  const skill = job.skills[0];
  console.assert(skill.id, "Skill should have id");
  console.assert(skill.name, "Skill should have name");
  console.assert(['csi', 'onet'].includes(skill.taxonomy), "Skill should have valid taxonomy");
}
```

## 🐛 Common Issues

### "No cached auth tokens found"

**Cause**: Auth tests haven't been run yet
**Solution**: Run auth tests first:
```bash
deno test --allow-all packages/supabase/functions/trpc/__tests__/auth.test.ts
```

### "Cached auth tokens have expired"

**Cause**: Tokens expired (default 1 hour)
**Solution**: Re-run auth tests to refresh tokens

### "Inbucket is not running"

**Cause**: Supabase not started or Inbucket failed to start
**Solution**: Restart Supabase:
```bash
pnpm supa stop
pnpm supa start
```

### TypeScript Errors in Test Files

**Cause**: Test files are checked in Edge Functions context but run with Deno
**Solution**: These errors are expected and will not affect test execution. Run tests with `deno test` command.

## 🔧 Common Testing Issues

### 1. "Could not find a relationship between 'job_skills' and 'skills'"
**Cause**: Query still using old `skills` table reference
**Fix**: Update query to use polymorphic pattern with `csi!csi_skill_id` and `onet!onet_occupation_id`

### 2. Empty skills array
**Possible causes**:
- No skills seeded in database
- Skills not properly linked to jobs
- Query not joining correctly

### 3. TypeError in skill transformation
**Cause**: Skill data structure doesn't match expected format
**Fix**: Check `transformJobSkills` function handles all edge cases

## 🎯 Best Practices

1. **Always run auth tests first** - Other tests depend on cached tokens
2. **Use test context** - Avoid manually managing auth tokens
3. **Test without auth first** - Verify endpoints properly reject unauthorized access
4. **Test RLS policies** - Ensure data isolation works correctly
5. **Clean descriptive names** - Test names should clearly describe what's being tested
6. **Handle expected failures** - Some tests may fail if features aren't implemented yet
