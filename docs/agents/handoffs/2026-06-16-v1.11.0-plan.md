# v1.11.0 plan — Worker MVP core screens (gated on QA clean-slate)

> Planning doc for the next coded release after v1.10.0 (design milestone).
> Companion to [`2026-05-30-v1.8.0-plan.md`](./2026-05-30-v1.8.0-plan.md).
> Two-phase shape: **clear the verification debt first, then build the worker
> MVP screens.** Decided 2026-06-16 with @clay.

## Context

- **45 open SC issues.** 33 sit in **In TestFlight** — built, QA-testable, but
  not yet validated to **Done**. Spread across three shipped releases:
  - **v1.7.0 (9)** — profile-API repair. Four 🔥 urgent: SC-90 (route shadowing),
    SC-91 (skill-search 404), SC-92/SC-93 (missing-relation 500s).
  - **v1.8.0 (12)** — jobs / applications / certs / onboarding audit fixes.
    Includes security fix SC-120 (PATCH lets a user reassign a job to an org
    they don't own).
  - **v1.9.0 (12)** — applications / prerequisites / jobs hardening.
- **v1.10.0 is a stalled design milestone.** App version bumped to 1.10.0
  (`06ef4b6ac`) but all three tickets are still **Todo**: SC-33 (Home design),
  SC-34 (Jobs design), SC-27 (UI-kit refactor — explicitly blocked on those
  designs + Robin). No shippable code came out of it yet.
- **v1.11.0** = this doc. Worker MVP core screens, **but only after** the 33
  In-TestFlight issues are validated to Done. Clean slate first (decision below).

## Decisions (2026-06-16, @clay)

1. **Release driver:** Worker MVP screens (feature-led — the natural unblock of
   the v1.10.0 design chain).
2. **QA debt:** **Clear all 33** In-TestFlight issues to Done *before* any new
   feature work begins. Slower start, clean slate.

## Phase 0 — Verification clean-slate (BLOCKS all of Phase 1)

Validate every In-TestFlight issue against the current TestFlight build and
promote to **Done**. Order by blast radius:

1. **v1.7.0 profile P0s first** — SC-90, SC-91, SC-92, SC-93 (🔥). Profile is
   foundational; a 500ing profile screen poisons every downstream flow.
   Then SC-94/95/96/97/99.
2. **v1.8.0 security + blockers** — SC-120 (auth/ownership) first, then SC-100,
   SC-101, SC-110, SC-114, SC-115, SC-117, then the 🔹/🔸 remainder.
3. **v1.9.0** — SC-103, SC-121, SC-127 (urgent), then the rest.

- Each issue: reproduce the original failure on TestFlight build → confirm
  fixed → move to Done. Log non-reproductions / regressions as new tickets.
- Owner: QA + @clay. This is validation time, not dev time.
- **Exit gate:** 0 issues in In TestFlight (or every remaining one has a written
  reason it's deferred). Only then does Phase 1 dev start.
