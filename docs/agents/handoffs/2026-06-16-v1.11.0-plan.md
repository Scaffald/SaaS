## Cross-cutting lessons to bake in (from the audit sweeps)

From [`scripts/audit/2026-06-10/STATUS-MATRIX.md`](../../../scripts/audit/2026-06-10/STATUS-MATRIX.md):

1. **Designs must include error + empty states.** Half the v1.7.0/v1.8.0 bugs
   were silent failures (`catch { return null }`). SC-33/34 should specify what
   the user sees on API error and on empty data, not just the happy path.
2. **UI-kit components consume typed `<Resource>Params`,** not loose `Record`
   props (SC-113/SC-124 class of drift). Fold into SC-27.
3. **Apply-flow idempotency-retry UX** (SC-106/SC-109): SC-34 should cover what
   the user sees when a retry collapses to the same submission.

## 2026-06-23 audit + local-dev notes

A fresh iPhone-viewport sweep ([`docs/agents/audits/2026-06-23-ui-audit/`](../audits/2026-06-23-ui-audit/))
surfaced that running the audit (or any local web session) against real
protected screens needs **all** of:

1. `pnpm supa start` (Docker) + `pnpm supa functions serve api` — the `api`
   edge function backs every data call incl. the prerequisites check.
2. Dev server started from `apps/scaffald` (`pnpm web`), not the repo root.
3. **A clean Metro cache when switching envs.** The app's Supabase client and
   the Scaffald SDK resolve their base URLs independently
   (`getSupabaseApiBaseUrl`); a stale cache from a prior `web:remote` run left
   auth pointing local but the SDK pointing at the remote dev project →
   split-brain 401/500s → a fully-onboarded user gets bounced to `/onboarding`.
   `expo start -c` (or wiping `metro-cache`) fixes it. The harness now
   preflights api health; the split-brain itself is a dogfooding finding worth
   its own ticket.
