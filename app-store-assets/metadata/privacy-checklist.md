## 1. App Tracking Transparency

- Plugin: `expo-tracking-transparency` (registered in [app.config.ts](../../apps/scaffald/app.config.ts))
- Usage description string: declared in both `ios.infoPlist.NSUserTrackingUsageDescription`
  and the plugin's `userTrackingPermission`. They MUST match.
- Runtime flow: AuthProvider fires `requestTrackingAuthorization()` once per install,
  after the user has signed in AND given cookie/performance consent. Idempotent.
- Behavior when denied:
  - PostHog `identify` / `alias` skipped — anonymous distinct id only.
  - Sentry `setUser` skipped; error capture still flows.
  - `captureEvent` continues with no PII.
- Status surface: Privacy & Data screen → "Tracking permission" panel, with
  deep-link to iOS Settings (Apple does not allow in-app re-prompts).

## 2. Apple Privacy Manifest (`PrivacyInfo.xcprivacy`)

Generated by Expo prebuild from `ios.privacyManifests` in [app.config.ts](../../apps/scaffald/app.config.ts).

| Field | Value |
|---|---|
| `NSPrivacyTracking` | `true` |
| `NSPrivacyTrackingDomains` | Derived from `EXPO_PUBLIC_POSTHOG_HOST` + `EXPO_PUBLIC_SENTRY_DSN_NATIVE` |
| `NSPrivacyAccessedAPITypes` | UserDefaults (CA92.1, C56D.1), FileTimestamp (C617.1, 0A2A.1, 3B52.1), SystemBootTime (35F9.1), DiskSpace (E174.1, 85F4.1) |
| `NSPrivacyCollectedDataTypes` | See mapping table below |

### Data type → linked / tracking / purpose mapping

| Data type | Linked to user | Tracking | Purposes |
|---|---|---|---|
| Email Address | Yes | No | App Functionality |
| Name | Yes | No | App Functionality |
| Phone Number | Yes | No | App Functionality |
| Photos or Videos | Yes | No | App Functionality |
| Coarse Location | Yes | No | App Functionality |
| Precise Location | Yes | No | App Functionality |
| User ID | Yes | **Yes** | App Functionality, Analytics |
| Device ID | Yes | **Yes** | Analytics |
| Product Interaction | Yes | **Yes** | Analytics, Personalization |
| Crash Data | No | No | App Functionality, Analytics |
| Performance Data | No | No | Analytics |

The three rows flagged `Tracking: Yes` are the ones that require ATT
authorization. They map 1:1 with the App Store Connect "Used for Tracking"
answers.

never speculatively. Apple rejects unused capability declarations.

## 5. User-rights surface

| Capability | Surface | Backing endpoint |
|---|---|---|
| View collected data | Settings → Privacy & Data → "Your Data Summary" | `CCPADataSummary` |
| Export data (GDPR Art. 20) | Settings → Privacy & Data → "Request Export" | `submitCCPARequest({type:'export'})` |
| Delete account (Apple 5.1.1(v) + CCPA) | Settings → Account → "Request Account Deletion" | `accountDeletion.requestWorkerDeletion` (signs out on success) |
| Correct data | Settings → Privacy & Data → "Request Correction" | `submitCCPARequest({type:'correction'})` |
| Opt out: sale / sharing / targeted ads / sensitive | Settings → Privacy & Data → "Opt-Out Preferences" | `setCCPAOptOut` |
| Revoke ATT | iOS Settings → Privacy & Security → Tracking → Scaffald | OS-level |
| Revoke performance cookies | Settings → Privacy → cookie banner | `CookieConsentProvider` |

## 6. Reviewer notes — paste into App Store Connect Notes for Review

```
Privacy & Tracking
- The App Tracking Transparency prompt appears after the user signs in for
  the first time (Apple/Google/email). To re-test the prompt: delete the
  app, reinstall, sign in. The prompt fires inside (protected) routes once
  consent and session are both ready.

  to Track" the app continues with anonymous analytics only.

  link to iOS Settings.

Account Deletion (Guideline 5.1.1(v))
- Settings → Account → "Request Account Deletion".
- Type DELETE in the confirmation field.
- The user is signed out immediately; backend deletion completes within
  30 days as required by GDPR/CCPA.

Test credentials and any region-specific variation: see the body of this
submission's Notes field.
```

## Update procedure

When a new feature lands that touches privacy:

1. Add the Info.plist key + plugin permission string to `app.config.ts`.
2. Add the data type to `NSPrivacyCollectedDataTypes`.
3. If it's a new third-party SDK that may track, add its host to
   `NSPrivacyTrackingDomains` (or its config-derived URL).
4. Update this checklist + App Store Connect → App Privacy in the same PR.
5. Re-run `expo prebuild` so `ios/scaffald/PrivacyInfo.xcprivacy` regenerates
   before the next EAS build.
