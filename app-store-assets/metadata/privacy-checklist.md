Last updated when ATT was removed (app does not track). Keep this in

## 1. App Tracking Transparency — NOT USED

Scaffald does **not** "track" as defined by App Store Review Guideline 5.1.2(i),
so there is no ATT prompt, no `NSUserTrackingUsageDescription`, and no
`expo-tracking-transparency` plugin.

Rationale: the only off-device recipients of user data are first-party service
providers — **PostHog** (product analytics, `disableGeoip: true`) and **Sentry**
(error monitoring). Their data is never combined with other companies' data for
advertising or measurement and is never shared with a data broker. There is no
IDFA access, no ad/attribution SDK (AppsFlyer, Branch, Facebook, Google Ads,
Adjust, Segment), and no SKAdNetwork.

- Analytics identity (PostHog `identify`/`alias`, Sentry `setUser` with PII) is
  gated solely on the in-app performance/cookie consent (`CookieConsentProvider`),
  handled in `AuthProvider`. Until the user opts in, analytics run with an
  anonymous distinct id and Sentry has no user object.
- If a genuine cross-app/advertising tracker is ever added, this section, the
  privacy manifest (`NSPrivacyTracking`, `NSPrivacyTrackingDomains`, the relevant
  `NSPrivacyCollectedDataTypeTracking` flags), the ATT key + plugin, and the
  App Store Connect App Privacy form must all be updated together.

## 3. App Store Connect → App Privacy answers

When updating the form, mirror the table above:

- "Do you or your third-party partners use data for tracking?" → **No**. PostHog
  and Sentry are first-party service providers; their data is not combined with
  other companies' data for advertising and is not shared with a data broker.
- For each data type, mark "Linked to User" or "Not Linked" per the table, with
  "Used for Tracking" = **No** for every row.
- Purposes per row, per the table.

## 5. User-rights surface

| Capability | Surface | Backing endpoint |
|---|---|---|
| View collected data | Settings → Privacy & Data → "Your Data Summary" | `CCPADataSummary` |
| Export data (GDPR Art. 20) | Settings → Privacy & Data → "Request Export" | `submitCCPARequest({type:'export'})` |
| Delete account (Apple 5.1.1(v) + CCPA) | Settings → Account → "Request Account Deletion" | `accountDeletion.requestWorkerDeletion` (signs out on success) |
| Correct data | Settings → Privacy & Data → "Request Correction" | `submitCCPARequest({type:'correction'})` |
| Opt out: sale / sharing / targeted ads / sensitive | Settings → Privacy & Data → "Opt-Out Preferences" | `setCCPAOptOut` |
| Revoke performance cookies | Settings → Privacy → cookie banner | `CookieConsentProvider` |

## 6. Reviewer notes — paste into App Store Connect Notes for Review

```
Privacy & Tracking
- Scaffald does not track users (Guideline 5.1.2(i)) and ships no ATT prompt.
  Off-device data goes only to first-party service providers: PostHog (product
  analytics, geolocation disabled) and Sentry (error monitoring). No IDFA, no
  ad/attribution SDKs, no data brokers, no cross-app linking.
- Analytics and error-report identity are linked to the account only after the
  user opts in via the in-app performance/cookie consent banner. Until then,
  analytics use an anonymous id and Sentry has no user object.
- See Settings → Privacy & Data for the data summary and privacy controls.

Account Deletion (Guideline 5.1.1(v))
- Settings → Account → "Request Account Deletion".
- Type DELETE in the confirmation field.
- The user is signed out immediately; backend deletion completes within
  30 days as required by GDPR/CCPA.

Test credentials and any region-specific variation: see the body of this
submission's Notes field.
```

## Update procedure

When a new feature lands that touches privacy:

1. Add the Info.plist key + plugin permission string to `app.config.ts`.
2. Add the data type to `NSPrivacyCollectedDataTypes`.
3. If it's a new third-party SDK that may track, add its host to
   `NSPrivacyTrackingDomains` (or its config-derived URL).
4. Update this checklist + App Store Connect → App Privacy in the same PR.
5. Re-run `expo prebuild` so `ios/scaffald/PrivacyInfo.xcprivacy` regenerates
   before the next EAS build.
